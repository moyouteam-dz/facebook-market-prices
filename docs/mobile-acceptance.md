# اختبار القبول على Android

هذا الاختبار هو البوابة الأخيرة قبل WebToApp. لا يعتبر التطبيق مقبولًا على الهاتف بمجرد نجاح CI أو build.

## المتطلبات

- هاتف Android حقيقي وChrome حديث.
- اتصال إنترنت.
- مفتاح Apify ومفتاح Gemini خاصان بالمستخدم ويُدخلان من شاشة الإعدادات فقط.
- صفحة Facebook عامة تحتوي منشورًا نصيًا بسعر، وصفحة أو منشورًا يحتوي صورة سعر إن أمكن.
- لا يُكتب المفتاح في GitHub أو الرابط أو سجل الاختبار.

## سيناريو القبول

1. افتح رابط GitHub Pages على Chrome وتحقق أن الواجهة عربية RTL وأن التنقل السفلي لا يغطي المحتوى.
2. افتح الإعدادات، أدخل مفتاح Apify واستخدم اختبار وحفظ المفتاح. أغلق الصفحة وافتحها مجددًا وتحقق أن التطبيق يعرف بوجود المفتاح بدون عرضه.
3. أضف صفحة Facebook عامة باسم وسوق، ثم عدّلها وعطّلها وفعّلها. تحقق أن رابط مجموعة Facebook مرفوض.
4. افتح التحديث. تحقق أن المصادر المفعلة محددة تلقائيًا. ابدأ تحديثًا يدويًا فقط.
5. راقب المراحل: جلب المنشورات، تحليل النص، ثم تحليل الصور عبر Gemini Vision. عند تفعيل Gemini تُرسل بيانات الصورة إلى Gemini لاستخراج الأسعار الظاهرة فقط.
6. أثناء تحليل الصور راقب Chrome وAndroid: لا crash، لا تجمد طويل، ولا إعادة تحميل للصفحة بسبب الذاكرة. معالجة الصور يجب أن تبقى منخفضة التوازي لتفادي ضغط الذاكرة والحصة.
7. بعد الاستخراج يجب فتح المراجعة قبل أي حفظ. عدّل منتجًا وسعرًا، احذف نتيجة خاطئة، وفعّل حفظ التصحيح لاسم منتج واحد.
8. اضغط حفظ النتائج ثم افتح السجل. تحقق من المنتج، السعر الأدنى والأقصى، السوق، التاريخ والمصدر.
9. أعد نفس التحديث. تحقق أن النتائج المطابقة لا تنشئ نسخًا مكررة في السجل.
10. نفّذ تحديثًا بعد تعطيل مصدر، وتحقق أنه لا يُستخدم.
11. افصل الإنترنت وحاول تحديثًا جديدًا. يجب أن تظهر رسالة خطأ مفهومة وألا تضيع البيانات المحفوظة.
12. صدّر CSV وافتحه على الهاتف. أنشئ Backup JSON وتحقق، بدون نشر محتواه، أنه لا يحتوي مفاتيح Apify أو Gemini.
13. بعد أخذ Backup، أضف أو غيّر بيانات ثم استرجع النسخة. تحقق أن السجل والمصادر والتصحيحات تعود وأن مفتاح Apify لا يأتي من ملف النسخة.
14. افتح روابط المصدر والمنشور من التطبيق. يجب ألا يسمح التطبيق ببروتوكولات script أو data أو file.
15. اختبر العرض Portrait ثم Landscape، مع تكبير خط Android إن أمكن. لا overflow أفقي ولا أزرار مخفية.

## نتيجة القبول

سجّل لكل بند: PASS أو FAIL، نوع الهاتف، إصدار Android، إصدار Chrome، وقت تحليل Gemini التقريبي لصورة واحدة، وأي crash أو reload. لا تسجل مفاتيح Apify أو Gemini.

لا تبدأ WebToApp حتى تكون البنود 1 إلى 15 PASS أو تكون الاستثناءات موثقة ومقبولة صراحة.
